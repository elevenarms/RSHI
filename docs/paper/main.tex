\begin{abstract}
\noindent
How best to load a dishwasher is a combinatorial, physical problem with an unusually honest reward:
a simulated wash decides which items come out clean \citep{composo2026dishwasherbench}. We use it
as a testbed for \ST, a self-improving multi-agent system built only from open, inexpensive models.
A deliberately weak loader (Nemotron-3.5-Super-VL, thinking off) is surrounded by a planner,
a vision critic, a coach and a librarian, all open Nemotron models on Crusoe serverless inference.
Between generations the team rewrites a typed genome of its own prompts, playbook, tool policy and
structure, and a deterministic gatekeeper keeps an edit only if it beats the incumbent on paired,
fresh tasks. The system works end to end, and quantifies a known physical effect: a cup stood
mouth up keeps half its grime. A first held-out exam showed $+17.8$\,pp; a 12-drill replication
showed $-0.3$\,pp (CI $\pm$13). We trace the gap to learned superstitions: the team accepted one
rule that is real physics and one that is noise, and the loader's sampling noise made them
indistinguishable. We give design rules to fix this.
\end{abstract}

\section{Introduction}
Recursive self-improvement is usually discussed for systems that rewrite their own weights. A
humbler, testable version keeps the model fixed and lets the system rewrite the \emph{scaffold}
around it: prompts, memory, tools and the division of labour
\citep{zelikman2023stop,hu2024adas,zhang2025dgm}. Such loops are hard to trust: the reward is often an LLM judge, which can be flattered
\citep{zheng2023judge}, a loop optimising a proxy finds its seams
\citep{skalse2022rewardhacking,krakovna2020specgaming,manheim2018goodhart}, and gains are usually
measured where they were selected.

We take the problem of loading a dishwasher, using DishwasherBench, Composo's open (MIT) benchmark
\citep{composo2026dishwasherbench}. It models one real machine (Bosch SMV4HAX40G): items are placed
with deterministic rigid-body physics (Jolt) through 13 MCP tools, then a GPU wash simulation
(WebGPU via Dawn) of the Eco~50 programme with one detergent capsule, calibrated on washes of the
real machine (parameter set \texttt{anchored-v8.owner-capsule}), decides which items are clean
against a threshold derived from the IEC~60436 scale \citep{iec60436_2025,en60436_2020,eilts2023roundrobin}.
An item scores its points only if it comes out clean. The reward is \emph{objective} (points over
points available), \emph{deterministic} (a load always settles and washes the same way, and every
episode is verifiable by replay) and \emph{unfakeable}: a bowl mouth-up under a dead spot of the
spray arm stays dirty however eloquently the agent describes it. It is also hard: not everything
fits, so the player chooses what to load as well as how; jets reach only part of the load
\citep{perezmohedano2015pept,perezmohedano2017integrated}; and choosing a subset under capacity is
a knapsack over strongly NP-hard 3D packing \citep{kellerer2004knapsack,martello2000threedim}.
Household benchmarks score symbolic goals
\citep{srivastava2021behavior,shridhar2020alfred,puig2018virtualhome,savva2019habitat}, and prior
dishwasher-loading work scores grasp success or agreement with a human preference
\citep{voysey2021dishwasher,jain2023transformers,kapelyukh2021myhouse,lin2021gnn}; to our knowledge
none scores whether the items come out clean, the gap DishwasherBench fills.

The benchmark, simulator, calibration, levels and harness are Composo's work
\citep{composo2026dishwasherbench}. Ours is \ST, the self-improving team, with its memory,
Gatekeeper, exam protocol and visualiser (Fig.~\ref{fig:studio}), plus cosmetic water, watch and turntable changes to the
benchmark's web client that touch neither simulation nor scoring. We asked whether cheap open
models can lift a weak loader by rewriting the system around it, keeping only changes that
measurably help. The honest answer is: not yet, and we can show why. Contributions:
\begin{itemize}
\item \ST, a team whose rewritable state is a typed, versioned \emph{genome}, edited only through six
typed operations, with the judging roles (memory accounting, acceptance) in deterministic code: the
team can change how it plays, never how it is graded.
\item A paired acceptance rule, a three-layer memory with shrunken Bayesian confidence, and a
held-out exam with a replication protocol (12 drills $\times$ 2 repeats).
\item A diagnosis of \emph{learned superstitions}, with a noise analysis, and design rules for
self-improving loops on noisy weak models: more pairs and repeats, a statistical acceptance test
instead of a fixed margin, and physics falsification of each learned rule before it is kept.
\end{itemize}

\section{Related Work}
\textbf{Scaffold self-improvement.} STOP recursively improves the improver around a fixed LM
\citep{zelikman2023stop}; ADAS's meta-agent programs new agents \citep{hu2024adas}; the Darwin
G\"odel Machine keeps self-edits that validate, in an open-ended archive \citep{zhang2025dgm};
G\"odel Agent and SICA rewrite their own logic or code \citep{yin2024godel,robeyns2025sica}. AFlow
searches workflows with MCTS and lets cheap models match expensive ones \citep{zhang2024aflow};
GPTSwarm optimises prompts and agent connectivity \citep{zhuge2024gptswarm}; FunSearch and
AlphaEvolve gate LLM proposals with automatic evaluators
\citep{romeraparedes2024funsearch,novikov2025alphaevolve}. Our Coach is a typed, constrained meta-agent in this line.

\textbf{Prompt and program optimisation} learns from scored histories, LLM mutation, compiled
programs and textual feedback \citep{yang2023opro,fernando2023promptbreeder,guo2023evoprompt,khattab2023dspy,opsahlong2024mipro,yuksekgonul2024textgrad,cheng2024trace};
GEPA's reflection on traces is closest to our Critic$\to$Coach loop \citep{agrawal2025gepa}.

\textbf{Memory and multi-agent systems.} Agents keep reflections, cross-task insights, skills and
workflows \citep{shinn2023reflexion,zhao2023expel,majumder2023clin,wang2023voyager,wang2024awm,park2023generative,packer2023memgpt};
unlike self-refinement \citep{madaan2023selfrefine}, our lessons are counted against physics. Role-based teams
\citep{wu2023autogen,hong2023metagpt,li2023camel,qian2023chatdev} and debate \citep{du2023debate}
follow fixed processes; ours edits its own structure. Voting and verified repeated sampling trade
compute for parameters \citep{li2024moreagents,brown2024monkeys,snell2024ttc}; our verifier is too slow to call per action.

\textbf{Search over loads.} Loading is constrained packing with a physical, black-box objective
\citep{wang2019stable,zhao2021online}; genetic algorithms \citep{holland1975adaptation,goldberg1989genetic},
CMA-ES over poses \citep{hansen2001cmaes}, quality-diversity \citep{mouret2015mapelites}, Bayesian
optimisation \citep{snoek2012practical} and MCTS over placement sequences
\citep{kocsis2006uct,browne2012mcts} are natural per-instance optimisers. We do not search loads
directly: every evaluation costs a wash, and the product is \emph{one load}, not a better loader,
so nothing transfers to a new set of items.

\section{Method}
\textbf{The team} (Table~\ref{tab:team}, Fig.~\ref{fig:loop}). In \ST{} the Loader plays through the
standard DishwasherBench harness tools \citep{composo2026dishwasherbench}, with renders as at most one image per request (the newest). Optionally a
Planner turns the level card and a memory brief into a per-item plan (rack, stance, what to leave
out). After each practice episode the Critic gets the item-by-item outcome (rack, stance, clean,
residue, retained water), plan, playbook and two renders of the final load, and writes up to five
tagged lessons with a polarity. The Coach
proposes edits; the Librarian condenses memory into a brief.

\textbf{Genome and typed edits.} A genome is an immutable record of everything the team may
rewrite: three prompts (Planner, loader preamble, Critic); a playbook of at most 25 tagged rules
with evidence links to lessons; team switches (\texttt{usePlanner}, \texttt{useMemoryBrief},
\texttt{preflightCheck}, which refuses \texttt{start\_cycle} before a read \texttt{check\_load}, and
the brief's lesson count); and loader settings (reasoning effort, images, denied tools, turn limit).
The Coach can change it only by \texttt{add\_rule}, \texttt{edit\_rule}, \texttt{remove\_rule},
\texttt{set\_prompt}, \texttt{set\_team} and \texttt{set\_loader}. A proposal carries a title and a
falsifiable hypothesis, changes one coherent thing, and is shown past rejections; ids hash content
and parent, so lineage is diffable. G0 is the bare loader: no planner, brief or preflight, an empty
playbook.

\textbf{Three-layer memory.} The \emph{episodic} layer keeps every training episode item by item;
the \emph{semantic} layer keeps lessons (from the Critic, and observed from placement statistics),
deduplicated on merge, with support $s$ and contradiction $c$ counts; the \emph{procedural} layer
keeps every genome and decision. Confidence is a Beta(1,1) posterior mean shrunk towards ignorance
while evidence is thin:
\begin{equation}
p=\tfrac{s+1}{n+2},\quad \kappa=\tfrac12+\big(p-\tfrac12\big)\tfrac{n}{n+K},\quad n=s+c,\ K=3,
\label{eq:conf}
\end{equation}
so one supporting episode gives $0.54$, five of five $0.72$, twenty of twenty $0.90$. A level's
brief lists smoothed clean rates $(k+1)/(m+2)$ of its kinds per rack and stance, then lessons with
$\kappa\ge0.5$ ranked by $\kappa\cdot\text{relevance}\cdot\log(1+n)$. Exam episodes are stored
apart and never read back.

\textbf{Gatekeeper.} Candidate $C$ and incumbent $I$ play the same fresh validation drills with the
same seeds. Let $P$ be the drills both played validly and $x_t$ the share on drill $t$; then
\begin{equation}
\bar\Delta=\tfrac{1}{|P|}\textstyle\sum_{t\in P}\big(x_t^{C}-x_t^{I}\big),\qquad
\text{accept}\iff \bar\Delta\ge\delta,
\label{eq:gate}
\end{equation}
and the decision is void if $|P|<3$. Agent failures (turn or token limit, nothing loaded) score what
they scored; \emph{invalid} episodes (provider or harness errors) are replayed on the same task and
seed up to twice, and drills still unpaired are dropped for both genomes.\footnote{In a pilot, HTTP 429s were first scored as agent failures and a generation was voided.} Pairing matters because episodes vary enormously (G0 scored 88\% on one Tutorial drill and 0\%
on a Weeknight drill); with deterministic physics it cancels drill difficulty. The accepted
candidate with the largest $\bar\Delta$ becomes the incumbent; its validation episodes are the next
practice set.

\textbf{Exam: what ``held-out'' means.} Training and validation drills come from DishwasherBench
course levels 1--4 (tutorial, lunch for four, weeknight dinner, breakfast), the exam from levels
5--7 (mixed family, baking day, dinner party) \citep{composo2026dishwasherbench}. These are new task
families with kinds and soils training never showed (baby bottle, spouted beakers, lunch tubs,
baking tray, tin, platter; burnt sugar, overnight soils). Nothing is learned from the exam.

\section{Experimental Setup}
All models run on Crusoe Managed (serverless) Inference via an OpenAI-compatible API, with a
client-side rate limiter and byte-stable prompts for prefix caching (83--90\% of input tokens hit
the cache in smoke runs). \textbf{Choosing a weak loader.} A saturated loader leaves the Gatekeeper
nothing to measure. On one 12-item drill, DeepSeek-V4.1-Flash and Qwen3.8-27B scored 100\%,
gpt-oss-120b 49\%, Nano-30B with thinking 41\% at ${\sim}6\times$ the wall time (without, it
looped); Nemotron-3.5-Super-VL without thinking scored 21\% (all it loaded clean) and is our
loader. A Lightning pilot was throttled by its shared endpoint to ${\sim}5$ calls/min.

\textbf{Protocol.} A drill is 12 items of a DishwasherBench level drawn by seed, cutlery in
proportion. The evolution run (\texttt{\RunId}) has \Generations{} generations: \PracticeTasks{}
baseline practice drills, \ProposalsPerGen{} proposals and \ValTasks{} paired fresh validation
drills per generation, $\delta=\Margin$, a \TurnCap-turn cap and 8 episodes in flight. G0 and the
champion then sat a 4-drill held-out exam and, separately, a \emph{replication}: 12 held-out drills
from levels 5--7, each played twice by both genomes. Washes use the fast tier (4\,mm blocks rather
than 2\,mm), whose verdicts agree with the official tier's on 91\% of the standard load and 97\%
of pieces on the course levels \citep{composo2026dishwasherbench}. G0 scored \BaselinePractice{}
in practice, loading few items but nearly all of them clean: it fails at commitment, not physics.

\textbf{Evolution.} The system ran end to end: the Gatekeeper accepted \Accepted{} of \Proposed{}

\textbf{Finding 1 (quantified, not discovered).} A cup stood mouth up keeps half its grime. In 108
deterministic fast-tier washes of every hollow kind in the course levels, each item alone (73
classifiable by resting stance), drinkware and ramekins were
always clean mouth down and never mouth up (Table~\ref{tab:hollow}). Bowls mouth up still washed
clean (8/8) but kept 1.17\,L of water each (CI 0.66--1.78); one mixing bowl held 2.9\,L and starved
the pump. Over 15 hollow items seen in both stances, mouth down adds 60\,pp to P(clean) (CI
33--87; odds ratio ${\approx}130$ with a 0.5 correction); no tilt from 0 to 45$^\circ$ beats
another. The effect is long known (phenomenon P01 \citep{composo2026dishwasherbench}); the number
is new, for one machine and programme, the fast tier, items alone and small $n$ per kind.

\textbf{Learned superstitions.} We report, with appropriate gravity, that our team became
superstitious. R2.1 is real physics: it is Finding 1. R1.1 is not. It rested on one dirty bowl in
two loads, and the controlled sweep washed every mouth-down bowl clean, 45$^\circ$ included. The
memory had never seen a mouth-up hollow item, so it learned ``mouth down'' from successes alone;
and the team's largest real loss, items left out (cereal bowls were left out 21 times and never
loaded), was never targeted. The Gatekeeper could not tell the true rule from the superstition,
because the loader's sampling noise swamps the margin: the same genome on the same drill differed
by 0.20 share on average between repeats (up to 0.80; one drill scored 0.000 and 0.803). With a
per-drill SD near 0.3, three or four paired drills cannot resolve a 3\,pp margin, and even 23
pairs resolve only about $\pm12$\,pp; resolving $\pm3$\,pp would take on the order of 400 pairs.
An ablation of the rules is in progress.

\textbf{Cost.} \WallTime; the loader used 38.24M input tokens (\CacheHit{} cached), the other
roles under 0.1M. Cost: \Cost.

\section{Discussion and Limitations}
The architecture held: physics scored, code decided, models proposed
\citep{zheng2023judge,amodei2016concrete}, and full logs let us find out \emph{why} a gain vanished. What failed is the statistics of selection
\citep{gelman2013forking,dwork2015reusable,benjamini1995fdr}: a fixed margin on three drills
accepted one true rule and one superstition with equal confidence. Three design rules follow for
self-improving loops on noisy weak models. (i)~Many more paired drills, with repeats per drill.
(ii)~A statistical acceptance test (a sequential test \citep{wald1945sequential} or a confidence
bound \citep{dror2018hitchhiker}) instead of a fixed margin. (iii)~\emph{Falsify the lesson, not
just score the genome}: test each learned rule with cheap controlled washes before it enters the
playbook, which a deterministic simulator makes possible. \emph{Limitations}: one machine, programme, detergent and
the fast tier; one evolution run; 23 pairs bound the effect only to ${\pm}12$\,pp.

\section{Conclusion}
A team of open models can rewrite its own system and keep only what measurably helps; ours learned
one true rule and one superstition and could not tell them apart. The fix is better evidence: more
pairs, real tests, physics checks of every lesson. Beyond that, \emph{we propose} (we have not done
it) the next recursion: a scaffold can only steer a noisy policy, so distil the team's best
trajectories, already logged token by token, into the weak loader by LoRA SFT on Crusoe Serverless
Fine-Tuning, which supports Nemotron-3.5-Lightning;\footnote{\url{https://docs.crusoecloud.com/serverless-fine-tuning/available-models}}
a Self-Serve Deployment would also escape the throttling. The aim is lower variance between
repeats, so the paired test gains power: the scaffold discovers, the Gatekeeper verifies,
fine-tuning consolidates. Recursive self-(home-)improvement needs a scientist on the team.
